# Protocol decisions and deviations log

All dates use 2026-07-15. “Before test performance” means the decision was made before any locked internal-test or external-model metric was calculated.

| Decision/change | Timing | Evidence and rationale | Outcome impact |
|---|---|---|---|
| Use the currently distributed Kaggle source (reported by its page as Version 2, 7,200 images) rather than assuming the older tracker-era file count. | Before training and test performance | The live public source had changed. Exact file-level hashes and retrieval date were frozen in the manifests and `source_provenance.json`. | Changes the source cohort; prevents falsely claiming use of an older release. |
| Exclude one entire cross-label perceptual-duplicate component (7 images) without relabelling. | Before training and test performance | The failed pre-exclusion audit showed the same visibly reused lesion image under glioma and meningioma labels. | Final analysis cohort is 7,193 images. Both the failed audit and excluded paths are retained. |
| Treat missing patient identifiers as residual leakage risk rather than claiming patient-level splitting. | Before training and test performance | The distributed filenames/metadata contain no patient IDs. Exact/perceptual duplicate components are only a fallback split unit. | Limits the strength of internal validation claims and bootstrap interpretation. |
| Reject BRISC as independent external validation. | Before locked-test model evaluation | The final-manifest exact-hash audit found 4,781/6,000 BRISC classification records reused from the development analysis cohort (79.7%). | BRISC cannot satisfy the external primary endpoint. Its masks may be used only for labelled internal-test XAI analysis. |
| Reject BDNeuro-MRI v7 as independent external validation. | After custom-CNN training started but before its locked-test evaluation; no EfficientNet training or external metric had occurred | Independent audit found 3,314/5,941 candidate images (55.8%) byte-identical to the development source and 4,490 (75.6%) within dHash Hamming distance ≤5. The distributed README also leaves consent/license attribution as placeholders, and the audit found perceptual-hash components crossing candidate splits and labels. | The candidate cannot satisfy the external primary endpoint. It was not used for training, tuning, calibration, or performance estimation. |
| Stop EfficientNet-B0 optimization after nine complete epochs. | After epoch 9 validation and before any EfficientNet locked-test evaluation | CPU-only training required about nine minutes per epoch. Epoch 9 produced the best validation accuracy (0.9744); validation loss (0.4252) had not improved over the epoch-8 minimum (0.4212). The new best-accuracy checkpoint was frozen before stopping. | The internal EfficientNet result is a resource-constrained comparator, not a fully protocol-conformant primary run. Calibration remains validation-only and the locked test is evaluated once from the frozen epoch-9 checkpoint. |
| Set DataLoader workers to 0 by default. | Before completed training | The restricted host disallowed PyTorch shared-memory workers. Single-process loading changes speed, not examples or optimization. | No endpoint change; improves portable reproducibility. |
| Label the 10-question RAG benchmark preliminary. | Before reporting retrieval metrics | Questions/relevance labels were created during system development and have not received independent domain-expert review. | Retrieval numbers are engineering results, not confirmatory manuscript evidence. |

No locked internal-test performance was used to make the data inclusion, split, external-candidate, or hyperparameter decisions above. BDNeuro-MRI was identified after custom-CNN optimization had begun, so its audit is recorded as a post-protocol candidate assessment, but it was rejected without viewing model performance on it.
